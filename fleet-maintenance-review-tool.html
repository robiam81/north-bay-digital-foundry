Fleet Maintenance Review Tool

A rules-based prototype that checks service intervals and data gaps, then ranks fleet vehicles for human review. It does not predict failures or determine whether a vehicle is safe to operate.

Import vehicle and service-history CSV files, apply your configured maintenance schedules, and see which tasks are current, due soon, overdue, or missing enough data to assess. An explainable review priority score helps order follow-up work. Fleet staff must verify the records, assess faults, and make operational decisions separately.

Review priority score Higher means review sooner; it does not measure failure risk or permission to operate. Always shown with each vehicle's maintenance-schedule status: current, due soon, overdue, or insufficient data.

Prototype · read before use

02 · How it works

From two CSV files to a review list

The tool is a command-line program that runs locally on a Windows machine with Python 3.12. It makes no network calls and has no accounts or telemetry; it reads the files you name and writes only where you tell it to.

  1. Import two CSV files. A vehicle inventory (current odometer and engine-hour readings) and a service history. The tool validates both first and reports every problem with its file, row, field, and a suggested fix.
  2. Apply your configured maintenance schedules. A rules file sets each task's interval by miles, engine hours, and calendar months for each asset class. Replace the bundled placeholder intervals with your own maintenance program.
  3. Classify every task. Each configured task on each vehicle is marked current, due soon, overdue, or insufficient data. The vehicle takes the most severe status among its tasks, and the task that set it is named.
  4. Order the fleet for review. Each vehicle gets a review priority score from five documented components, shown next to its maintenance-schedule status. The explain command lists every component's inputs and contribution for a single vehicle.

Maintenance-schedule status

StatusWhat it means (default thresholds)
CurrentLess than 85% of the interval used on every measured criterion.
Due soonAt least 85% of an interval used, but not yet at 100%.
OverdueAt or past an interval.
Insufficient dataNo matching service record, a reading not recorded at the last service, a missing current reading, or a current reading below the last-service reading. Missing data is never treated as current.

Review priority score

Review priority score Higher means review sooner; it does not measure failure risk or permission to operate. The score is always reported beside the vehicle's maintenance-schedule status — current, due soon, overdue, or insufficient data — and the task that set that status. Read the two together, never the score alone.

The score runs from 0 to 100 and is built from five weighted components: how close the most-due task is, how far past due it is, how much other work is stacking up, repeated corrective work, and how much of the record is missing. The weights, thresholds, and bands are all set in the rules file and documented with the tool. Data gaps alone cannot push a vehicle into the highest band, so vehicles with insufficient data should be worked from their own list, not only by score.

Quickstart (Windows PowerShell)

From the folder where you saved the release files, check the download against the published hash, then install and run the bundled synthetic demo:

Get-FileHash .\nbdf_fleet-0.1.0-py3-none-any.whl -Algorithm SHA256
Get-Content .\SHA256SUMS.txt
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install .\nbdf_fleet-0.1.0-py3-none-any.whl
.\.venv\Scripts\nbdf-fleet.exe demo

The two hash strings must match. The wheel has no dependencies, so the install works offline. To use your own data, create a workspace, fill in the two CSV templates, replace the placeholder intervals in rules.toml, then validate and analyze:

.\.venv\Scripts\nbdf-fleet.exe init my-fleet
.\.venv\Scripts\nbdf-fleet.exe validate my-fleet\vehicles.csv my-fleet\service_history.csv --config my-fleet\rules.toml
.\.venv\Scripts\nbdf-fleet.exe analyze  my-fleet\vehicles.csv my-fleet\service_history.csv --config my-fleet\rules.toml --as-of 2026-06-30 --output-dir my-fleet\out
.\.venv\Scripts\nbdf-fleet.exe explain  my-fleet\vehicles.csv my-fleet\service_history.csv LD-103 --config my-fleet\rules.toml --as-of 2026-06-30

Keep real fleet data on your own machine. The README included with the download covers every command, the input schema, exit codes, and the full scoring method.

03 · Potential impact

Why build it

Many small and mid-size public works fleets track maintenance in spreadsheets or paper logs, with no consistent way to see which vehicles need attention first. This tool offers a low-cost, transparent way to bring structure to that review: it applies the same documented rules to every vehicle, every time, so prioritization doesn't depend on who happens to remember which truck is due for service.

Because the scoring method and thresholds are fully configurable and disclosed, agencies can adapt it to their own maintenance schedules rather than trust an opaque model. The goal is to save staff time on the first pass of fleet review, not to replace their judgment. It is a prototype today, but it's built so a validated predictive model could extend it later without discarding the work already done.

Review priority score Higher means review sooner; it does not measure failure risk or permission to operate. Prioritization always pairs the score with each vehicle's maintenance-schedule status: current, due soon, overdue, or insufficient data.

04 · Limitations

Limitations and caveats

  • Prototype status. This is a rules-based heuristic, not a validated failure-prediction model. It does not predict failures, estimate probabilities, or forecast costs.
  • Placeholder intervals. The default maintenance intervals are placeholders, not manufacturer or agency schedules. The tool displays this same warning at runtime until you replace them and say so in the rules file.
  • Not validated against real fleet data. The bundled and example datasets are synthetic.
  • Requires calibration before operational use. Intervals, thresholds, weights, and bands must be set to your maintenance program and reviewed by people who know the fleet.
  • Requires human oversight throughout. Fleet staff must independently verify records and make operational and safety decisions. The tool does not do this.
  • Readings are trusted as entered. A wrong but plausible odometer or engine-hour reading passes validation and drives the result.
